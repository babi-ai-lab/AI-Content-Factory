# نقشه راه محصول AI Content Factory

این سند وضعیت واقعی محصول را نشان می‌دهد. قابلیت انجام‌شده فقط زمانی علامت می‌خورد که در کد و زیرساخت پیاده‌سازی شده باشد؛ موارد نیازمند تست یا تنظیمات جداگانه، آماده عرضه عمومی محسوب نمی‌شوند.

## چشم‌انداز

تبدیل AI Content Factory به یک فضای کاری بازاریابی محتوایی برای کسب‌وکارهای کوچک و متوسط؛ با تولید باکیفیت، مدیریت برند، کمپین، برنامه‌ریزی، تحلیل و کنترل هزینه.

## وضعیت فعلی

### انجام‌شده
- [x] ورود و ثبت‌نام با Supabase Auth، تأیید ایمیل، بازیابی رمز عبور و حذف حساب با تأیید رمز فعلی
- [x] تولید بسته محتوایی با موتور پردازش متصل و مدل جایگزین
- [x] پشتیبانی از ۹ نوع کسب‌وکار و ۱۰ قالب تخصصی
- [x] ذخیره تاریخچه و جداسازی داده کاربران با RLS
- [x] وضعیت بازبینی محتوا در تاریخچه با چهار حالت، فیلتر وضعیت و ثبت زمان آخرین تغییر؛ گردش فعلی تک‌حسابی است
- [x] ویرایش، کپی، خروجی TXT/JSON، جست‌وجو، پوشه، برچسب و علاقه‌مندی
- [x] نسخه‌بندی محتوا، snapshot و بازگردانی نسخه
- [x] صفحه‌بندی تاریخچه و پشتیبان کامل تا سقف ۱۰٬۰۰۰ رکورد
- [x] احراز هویت API، اعتبارسنجی ورودی و محدودیت اندازه بدنه
- [x] rate limit پایدار و اتمیک در PostgreSQL (۸ درخواست در ۱۰ دقیقه)
- [x] CI برای audit وابستگی‌های production، تست، typecheck و build
- [x] دانش معتبر برند شامل واقعیت‌های تأییدشده، شواهد قابل اثبات، FAQ و ادعاهای ممنوع؛ استفاده در پرامپت و بررسی عبارت‌های ممنوع
- [x] چک‌لیست ساختاری کیفیت محتوا
- [x] تقویم محتوایی هجری شمسی برای برنامه‌ریزی دستی
- [x] داشبورد تحلیل با تجمیع سمت PostgreSQL
- [x] ثبت مصرف توکن و تعداد تولیدهای موفق؛ بدون محدودیت ماهانه
- [x] مدیریت کمپین بازاریابی با هدف، مخاطب، کانال، وضعیت و چک‌لیست شش‌مرحله‌ای
- [x] اتصال امن محتواهای ذخیره‌شده به کمپین‌ها با RLS و مالکیت مشترک
- [x] انتقال هدف و مخاطب کمپین به فرم تولید محتوا
- [x] تولید متن اصلی و تبلیغ با راهنمای اختصاصی کانال
- [x] اتصال خودکار محتوای ذخیره‌شده به کمپین فعال
- [x] ثبت دستی شاخص‌های عملکرد کمپین و محاسبه KPIهای پایه
- [x] راهنمای شروع سریع برای حساب‌های بدون تاریخچه
- [x] صفحه معرفی عمومی محصول، FAQ و متادیتای فارسی
- [x] اطلاع‌رسانی و ثبت تأیید پردازش داده توسط سرویس محتوای متصل پیش از تولید
- [x] ثبت دستی بودجه، هزینه، نمایش، کلیک، سرنخ، تبدیل و درآمد کمپین
- [x] محاسبه KPIهای CTR، CPL، CPA، نرخ تبدیل، مصرف بودجه و ROAS
- [x] نمونه اولیه backend برای Instagram OAuth و انتشار تصویر/ریلز در مخزن موجود است؛ رابط کاربری فعلاً پنهان و قابلیت برای کاربران غیرفعال است. فعال‌سازی دوباره فقط پس از تصمیم محصول، تکمیل Meta App و آزمون end-to-end.

- [ ] آزمون جداسازی داده دو کاربر و بازبینی کامل RLS همه جدول‌ها

- [x] افزودن دامنه Production به فهرست Redirect URLs در Supabase Auth و آزمون لینک تأیید
- [x] تنظیم SMTP اختصاصی و آزمون واقعی ایمیل تأیید؛ [ ] آزمون جداگانه بازیابی رمز عبور
- [ ] ساخت تقویم اختصاصی کمپین و گزارش مقایسه‌ای چند کمپین

- [x] افزودن منبع حقیقت برند، شواهد و FAQ به تولید و کنترل عبارت‌های ممنوع.

- [ ] مقایسه بصری نسخه‌ها و یادداشت‌گذاری نسخه‌ها
- [x] آزمون smoke زمان‌بندی‌شده برای health، صفحه اصلی، CTA، assetها و عدم بازگشت رابط قدیمی اینستاگرام؛ نخستین اجرای موفق Production هنوز باید ثبت شود.
- [ ] پایش خطا، latency و سلامت سرویس
- [ ] پشتیبان‌گیری و آزمون واقعی بازیابی
- [ ] بررسی ظرفیت، پایداری و هزینه زیرساخت قبل از عرضه عمومی گسترده
- [ ] تکمیل سیاست حریم خصوصی و شرایط استفاده با اطلاعات حقوقی مالک محصول و بازبینی حقوقی
- [ ] بررسی تنظیم Supabase Auth برای محافظت در برابر رمزهای افشاشده
- [ ] تست دسترس‌پذیری، موبایل و مرورگرهای اصلی

## مسیر توسعه

### فاز ۰ — تثبیت مهندسی و قابلیت اطمینان
**وضعیت: پایه انجام‌شده؛ آزمون عملیاتی باقی است**
- CI برای نصب وابستگی‌ها، audit، تست، typecheck و build
- اعتبارسنجی سمت سرور و کنترل درخواست‌های حجیم
- تست خودکار منطق دامنه و کنترل کیفیت

**ادامه:** تست مرورگر/یکپارچه، پایش خطا و جداسازی منطق دامنه از اجزای رابط کاربری.

### فاز ۱ — تجربه محصول و ورود کاربر
**وضعیت: نسخه اول انجام‌شده**
- داشبورد و تاریخچه
- وضعیت‌های بارگذاری و خالی
- رابط فارسی و واکنش‌گرایی

**ادامه:** راهنمای تعاملی پیشرفته، پیام‌های خطای مفید و دسترس‌پذیری.

### فاز ۲ — موتور تولید حرفه‌ای
**وضعیت: نسخه اول انجام‌شده**
- دانش معتبر برند (واقعیت‌ها، شواهد، FAQ و ادعاهای ممنوع) و قالب‌های تخصصی
- استفاده از هویت برند در تولید
- کنترل ساختاری کیفیت

**ادامه:** ورود فایل و URL به دانش برند، بررسی معنایی ادعاها با ارجاع به منبع، مقایسه نسخه‌ها و خروجی‌های قابل تنظیم.

### فاز ۳ — کمپین و عملیات محتوا
**وضعیت: نسخه اول انجام‌شده**
- تقویم محتوایی شمسی
- مدیریت کمپین و چک‌لیست اجرا

**ادامه:** تقویم اختصاصی، گردش تأیید چندنفره و نقش‌محور، خروجی دسته‌ای و گزارش مقایسه‌ای چند کمپین.

### فاز ۴ — رسانه و چندرسانه‌ای
**وضعیت: نسخه اول مستقر؛ migrationها اعمال شده‌اند؛ آزمون نهایی تولید تصویر با نشست کاربر لازم است**
- [x] تولید تصویر تبلیغاتی 1K با مدل تصویر متصل
- [x] فضای ذخیره‌سازی خصوصی، لینک امضاشده، RLS و سهمیه اتمیک ۵ تصویر در ساعت
- [x] اتصال دارایی تصویری به محتوای ذخیره‌شده
- [x] کتابخانه رسانه با مرور ۴۰ تصویر اخیر، لینک خصوصی موقت و حذف امن فایل و metadata
- [x] تولید پنج تصویر هماهنگ برای کاروسل از پنج متن استوری تأییدشده؛ نمایش متن هر اسلاید کنار تصویر
- [x] ویرایش متن فارسی هر اسلاید و خروجی PNG جداگانه با ابعاد 1080×1350
- [ ] دانلود یک‌جای پنج اسلاید در قالب ZIP و قالب‌های طراحی قابل ویرایش
- [ ] ارائه‌دهنده جایگزین و سیاست کنترل هزینه

**معیار خروج:** کنترل هزینه، حق استفاده، محدودیت فایل، امنیت آپلود و حذف فایل.

### فاز ۵ — درآمدزایی و همکاری تیمی
**وضعیت: عمداً غیرفعال**
- پلن‌ها، سهمیه‌ها و پرداخت
- تیم‌ها، دعوت اعضا و نقش‌ها

**معیار خروج:** فقط پس از تصمیم و تأیید صریح مالک محصول؛ در نسخه فعلی تمام امکانات رایگان و بدون سهمیه ماهانه‌اند.

### فاز ۶ — امنیت، مقیاس و عملیات
**وضعیت: پایه امنیتی انجام‌شده؛ تکمیل لازم است**
- RLS مالکیت‌محور و rate limit توزیع‌شده
- بازبینی امنیتی و آزمون جداسازی کاربران
- ثبت رخداد ساختاریافته و رصد خطا/تاخیر
- سیاست نگهداری، حذف و خروجی داده
- پشتیبان‌گیری و بازیابی مستند
- بهینه‌سازی هزینه، عملکرد و ظرفیت

## اصول تصمیم‌گیری

1. ابتدا امنیت داده و صحت عملیات؛ سپس امکانات جدید.
2. هیچ آمار، قیمت، نتیجه یا ویژگی کسب‌وکار در خروجی AI جعل نشود.
3. هیچ کلید محرمانه‌ای در کد مرورگر، Git یا گزارش‌ها قرار نگیرد.
4. هر قابلیت با تست، مدیریت خطا و طراحی موبایل تحویل شود.
5. تغییر دیتابیس باید migration نسخه‌دار، قابل بازبینی و تا حد امکان برگشت‌پذیر داشته باشد.
6. هزینه API، پرداخت، دامنه و سرویس ثالث بدون تأیید صریح مالک ایجاد نشود.
7. حذف داده واقعی، تغییر سیاست امنیتی حساس یا فعال‌سازی پرداخت نیازمند تأیید مالک است.
