# نقشه راه محصول AI Content Factory

این سند وضعیت واقعی محصول را نشان می‌دهد. قابلیت‌های انجام‌شده با «انجام‌شده» مشخص شده‌اند؛ موارد دیگر تا زمان پیاده‌سازی و آزمون، وعده یا قابلیت فعال محسوب نمی‌شوند.

## چشم‌انداز

تبدیل AI Content Factory از یک ابزار تولید متن به یک فضای کاری بازاریابی محتوایی برای کسب‌وکارهای کوچک و متوسط؛ با گردش‌کار قابل اتکا، خروجی قابل ویرایش، مدیریت برند، تحلیل عملکرد و کنترل هزینه.

## وضعیت فعلی

### انجام‌شده
- [x] ورود و ثبت‌نام با Supabase Auth
- [x] تولید بسته محتوایی با Gemini و مدل جایگزین
- [x] پشتیبانی از ۹ نوع کسب‌وکار
- [x] ۱۰ قالب تخصصی تولید محتوا با اعتبارسنجی سمت سرور
- [x] ذخیره تاریخچه در Supabase و جداسازی داده کاربران با RLS
- [x] ویرایش، کپی و خروجی TXT/JSON
- [x] جست‌وجو، پوشه، برچسب، علاقه‌مندی و خروجی گروهی JSON
- [x] احراز هویت API، اعتبارسنجی ورودی و محدودیت واقعی اندازه بدنه
- [x] تست‌های خودکار برای ورودی، rate limit، پروفایل برند، قالب‌ها و کنترل کیفیت
- [x] CI برای audit وابستگی‌های production، تست، typecheck و build
- [x] ارتقای Next.js 16، React 19 و Node.js 24
- [x] داشبورد تحلیلی حساب بر اساس تاریخچه بارگذاری‌شده
- [x] پروفایل برند پایدار و جداگانه برای هر حساب
- [x] چک‌لیست ساختاری کیفیت محتوا و بررسی واژگان برند
- [x] تقویم محتوایی ماهانه هجری شمسی با ناوبری ماه، دریافت تمام برنامه‌های ماه از کل تاریخچه و تغییر سریع زمان انتشار
- [x] تاریخچه نسخه‌های قبلی محتوا، snapshot و بازگردانی نسخه

- [x] بهینه‌سازی چهار policy جدول تاریخچه برای RLS initplan

## مسیر توسعه

### فاز ۰ — پایه مهندسی و قابلیت اطمینان
**وضعیت: انجام‌شده در سطح پایه**
- CI برای نصب وابستگی‌ها، audit، تست، typecheck و build
- مستندات و متغیرهای محیطی همگام با کد
- تست خودکار اعتبارسنجی ورودی، اندازه بدنه، JSON/UTF-8، rate limit و کنترل کیفیت
- اعتبارسنجی سمت سرور و کنترل درخواست‌های حجیم

**ادامه لازم:** جداسازی منطق دامنه از رابط کاربری بزرگ فعلی و افزودن تست مرورگر/یکپارچه.

### فاز ۱ — تجربه محصول و تحلیل
**وضعیت: نسخه اول انجام‌شده**
- داشبورد شاخص‌ها بر اساس داده‌های واقعی حساب
- فیلتر بازه زمانی، روند تولید، توزیع نوع محتوا و نوع کسب‌وکار
- وضعیت‌های بارگذاری، خالی و واکنش‌گرایی موبایل

**محدودیت فعلی:** حداکثر ۵۰ محتوای اخیر در رابط بارگذاری می‌شود؛ تحلیل تمام تاریخچه نیازمند صفحه‌بندی یا تجمیع سمت سرور است.

### فاز ۲ — موتور تولید حرفه‌ای
**وضعیت: نسخه اول انجام‌شده**
- پروفایل برند: مخاطب، ارزش پیشنهادی، واژگان ترجیحی/ممنوع و CTA
- استفاده از هویت برند در تولیدهای بعدی
- ۱۰ قالب تخصصی برای اهداف و شیوه‌های متفاوت بازاریابی
- کنترل کیفیت ساختاری خروجی و واژگان برند

**ادامه لازم:** نسخه‌بندی خروجی‌ها، مقایسه و بازگردانی نسخه، و بازبینی دقیق‌تر ادعاهای بدون پشتوانه.

### فاز ۳ — برنامه‌ریزی و عملیات محتوا
**وضعیت: برنامه‌ریزی انتشار نسخه اول انجام‌شده**
- تعیین زمان انتشار برای هر بسته
- نمایش انتشارهای پیش‌رو و موعدهای گذشته
- باز کردن محتوا از تقویم

**ادامه لازم:** مدیریت کمپین، وضعیت پیش‌نویس/بازبینی/تأیید، خروجی دسته‌ای و انتشار خودکار فقط پس از اتصال رسمی شبکه‌ها.

### فاز ۴ — رسانه و چندرسانه‌ای
**وضعیت: برنامه‌ریزی نشده در کد**
- تولید تصویر با ارائه‌دهنده قابل تعویض
- کتابخانه فایل و مدیریت دارایی
- اتصال خروجی تصویر به کمپین و محتوا
- تولید ویدئو فقط با بررسی هزینه، محدودیت ارائه‌دهنده و تجربه کاربری

**معیار خروج:** کنترل هزینه، حق استفاده، محدودیت فایل و پردازش امن.

### فاز ۵ — SaaS و درآمدزایی
**وضعیت: برنامه‌ریزی نشده در کد**
- پلن رایگان/پولی و سهمیه شفاف
- اندازه‌گیری مصرف بر اساس کاربر و مدل
- پرداخت از طریق ارائه‌دهنده سازگار با کشور/بازار هدف
- پنل مدیریت اشتراک، فاکتور و لغو
- تیم‌ها، دعوت اعضا و نقش‌ها

**معیار خروج:** هیچ پرداخت یا محدودیت پولی بدون تأیید مالک محصول و تنظیمات درگاه فعال نمی‌شود.

### فاز ۶ — امنیت، مقیاس و عملیات
**وضعیت: پایه امنیتی انجام‌شده؛ مقیاس‌پذیری باقی‌مانده**
- احراز هویت API و اعتبارسنجی بدنه
- RLS مالکیت‌محور و بهینه‌سازی auth.uid()
- rate limit توزیع‌شده و مقاوم در برابر چند نمونه سرور
- ثبت رخداد ساختاریافته و رصد خطا/تاخیر
- سیاست نگهداری، حذف و خروجی داده
- آزمون نفوذ و بازبینی RLS
- پشتیبان‌گیری و بازیابی مستند
- بهینه‌سازی هزینه و عملکرد

**محدودیت فعلی:** leaked-password protection در تنظیمات Auth غیرفعال است و سرویس Render روی پلن Free اجرا می‌شود. انتشار مستقیم پست/ریلز دستی فعال شده؛ زمان‌بندی خودکار و تأیید Meta App برای مشتریان عمومی باقی مانده است.

## اصول تصمیم‌گیری

1. ابتدا امنیت داده و صحت عملیات؛ سپس امکانات جدید.
2. هیچ داده، آمار، قیمت، نتیجه یا ویژگی کسب‌وکار در خروجی AI جعل نشود.
3. هیچ کلید محرمانه‌ای در کد مرورگر، Git یا گزارش‌ها قرار نگیرد.
4. هر قابلیت با تست، مدیریت خطا و طراحی موبایل تحویل شود.
5. مهاجرت دیتابیس باید نسخه‌دار، قابل بازبینی و تا حد امکان برگشت‌پذیر باشد.
6. هزینه‌های API، پرداخت، دامنه و سرویس‌های ثالث بدون تأیید صریح مالک ایجاد نشود.
7. انتشار production، حذف داده واقعی، تغییر سیاست امنیتی یا فعال‌سازی پرداخت نیازمند تأیید مالک است.
