# مدل داده MySQL برای مهاجرت ParsPack

این طرح از قابلیت‌های ثبت‌شده در README فعلی استخراج شده است: حساب کاربر، حداکثر ۱۰ برند، تولید و نسخه‌بندی محتوا، گردش بازبینی، پوشه/برچسب/علاقه‌مندی، کمپین و سنجه‌ها، رسانه خصوصی، آمار مصرف و محدودسازی درخواست.

## فایل migration
`database/migrations/001_initial_schema.sql`

هدف MySQL 8.0.16+ یا MariaDB 10.6+، موتور InnoDB و کدگذاری utf8mb4 است. تمام زمان‌ها UTC ذخیره می‌شوند و تاریخ شمسی فقط در رابط/لایه برنامه نمایش داده می‌شود.

## تصمیم‌های مهم
- شناسه‌های حساب از نوع UUID متنی‌اند تا امکان نگاشت شناسه Supabase در `legacy_auth_id` وجود داشته باشد.
- `password_hash` در ابتدا می‌تواند NULL باشد؛ رمز عبور Supabase را بدون آزمون سازگاری و فرآیند امن انتقال نمی‌دهیم. برای حساب‌های منتقل‌شده احتمالاً باید بازیابی/تنظیم مجدد رمز انجام شود.
- اطلاعات برند به‌صورت JSON نگهداری می‌شود تا واقعیت‌های تأییدشده، شواهد، FAQ و ادعاهای ممنوع از بین نروند.
- محتوای اصلی و نسخه‌های تاریخی در دو جدول جدا ذخیره می‌شوند.
- مبلغ‌ها DECIMAL هستند؛ هرگز مبلغ مالی را با FLOAT/DOUBLE ذخیره نکنید.
- رسانه فقط metadata و storage key دارد. فایل واقعی باید خارج از document root نگهداری شود.
- محدودسازی درخواست در جدول مستقل با عملیات اتمیک تراکنشی پیاده‌سازی می‌شود.
- این migration هنوز شامل کیف پول، اشتراک و سفارش پرداخت نیست؛ چون محصول فعلی طبق README رایگان است و درگاه/اشتراک فعال ندارد. این بخش در migration جداگانه و همراه با دفترکل تغییرناپذیر و idempotency اضافه می‌شود.

## ترتیب مهاجرت
1. گرفتن backup کامل از PostgreSQL و Storage و نگهداری امن خارج از webroot.
2. ساخت جداول خالی روی دیتابیس جدید.
3. واردکردن کاربران با حفظ UUID اصلی در `legacy_auth_id` و نگاشت به شناسه داخلی.
4. انتقال برندها، محتوا، نسخه‌ها، کمپین‌ها، سنجه‌ها و metadata رسانه با شمارش رکوردها و کنترل مالکیت.
5. انتقال فایل‌های باینری Storage به پوشه خصوصی هاست، بررسی MIME/حجم و تطبیق checksum.
6. اجرای تست‌های مالکیت، حذف حساب، خروجی پشتیبان و بازیابی.
7. فقط پس از تأیید صحت داده، تغییر مسیر Production؛ امکان rollback باید حفظ شود.

## مواردی که هنوز باید با migrationهای واقعی Supabase تطبیق داده شوند
- نام و ساختار دقیق جدول‌ها/ستون‌ها و enumهای فعلی
- جزئیات داده‌های JSON برند و خروجی تولید
- ساختار تاریخچه نسخه و متادیتای رسانه
- قیود و سیاست‌های RLS و قواعد حذف/نگهداری
- جداول rate limit و هرگونه داده عملیاتی دیگر

این فایل طرح اجرایی اولیه است، نه ادعای تکمیل مهاجرت یا آماده‌بودن برای اجرای Production.
