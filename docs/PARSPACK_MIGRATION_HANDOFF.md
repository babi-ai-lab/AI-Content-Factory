# وضعیت تحویل مهاجرت ParsPack

## نتیجه فعلی
این شاخه یک پایه فنی قابل بررسی برای بازنویسی PHP فراهم می‌کند، اما هنوز نسخه قابل انتشار یا جایگزین Production نیست.

## آنچه در این شاخه اضافه شده
- سند معماری مهاجرت به PHP اختصاصی و MySQL داخلی ParsPack
- طرح اولیه جداول MySQL برای کاربران، نشست‌ها، توکن‌های احراز هویت، برندها، محتوا، نسخه‌ها، کمپین‌ها، سنجه‌ها، رسانه و مصرف
- bootstrap و تنظیمات نمونه PHP 8.1+
- اتصال PDO با prepared statements و مدیریت خطای بدون افشای اطلاعات
- تنظیمات نشست با HttpOnly، Secure روی HTTPS و SameSite
- ابزار CSRF
- سرویس پایه ثبت‌نام/ورود/خروج با password_hash/password_verify، session regeneration و ثبت نشست در دیتابیس
- بررسی نشست جاری با رکورد پایدار و تاریخ انقضا در دیتابیس
- endpoint سلامت محدود و بدون افشای جزئیات

## چه چیزهایی هنوز تحویل نشده‌اند
- بازنویسی کامل رابط Next.js/React به HTML/CSS/JavaScript
- APIهای واقعی تولید محتوا، تاریخچه، نسخه‌بندی، پروفایل برند، کمپین، تقویم، تحلیل و استودیوی رسانه
- انتقال و تطبیق دقیق تمام migrationهای Supabase و ساختار واقعی داده‌ها
- ایمیل تأیید، بازیابی رمز، محدودسازی تلاش ورود و مسیرهای عمومی احراز هویت
- انتقال فایل‌های Storage و تطبیق checksum
- کیف پول/اشتراک/درگاه ریالی (در نسخه فعلی محصول هنوز پرداخت فعال نیست)
- تست‌های واحد، یکپارچه، امنیتی و مرورگر برای PHP
- تست روی نسخه PHP و MySQL واقعی حساب ParsPack
- نصب روی app.eltbabak.ir و آزمون staging
- مهاجرت داده واقعی، تغییر DNS/Document Root یا تغییر مسیر Production

## محدودیت مدل هوش مصنوعی
هاست اشتراکی فعلی برای اجرای inference مدل‌های بزرگ مناسب فرض نمی‌شود. داده‌ها، نشست‌ها، منطق کسب‌وکار و فایل‌ها می‌توانند روی ParsPack باشند؛ تولید مدل فقط با یک پردازشگر خارجی مجاز یا با محدودکردن محصول به تولید قاعده‌محور/قالبی ممکن است. هیچ provider یا هزینه‌ای بدون تصمیم مالک فعال نمی‌شود.

## شرط انتشار
این شاخه فقط پس از تکمیل موارد بالا، تست سازگاری روی هاست، تهیه backup قابل بازیابی و آزمون rollback می‌تواند برای انتشار بررسی شود. شاخه main و نسخه فعلی نباید تا آن زمان جایگزین شوند.

## اقدام لازم از مالک هاست
در زمان آماده‌سازی staging باید مشخصات PHP extensions، نسخه MySQL/MariaDB، امکان Cron، مسیر document root و امکان ساخت دیتابیس/کاربر جداگانه بررسی شود. اطلاعات محرمانه فقط در cPanel وارد شوند و هرگز در GitHub ثبت نشوند.
