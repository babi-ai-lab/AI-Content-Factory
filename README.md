# AI Content Factory

وب‌اپلیکیشن فارسی برای تولید، مدیریت و برنامه‌ریزی محتوای بازاریابی کسب‌وکارها.

## قابلیت‌های فعلی

- ورود و ثبت‌نام با Supabase Auth
- تولید کپشن، سناریوی ریلز، پنج استوری و متن تبلیغاتی با Gemini
- پشتیبانی از ۹ نوع کسب‌وکار
- ۱۰ قالب تخصصی تولید محتوا: متعادل، آموزشی، معرفی محصول، تجربه مشتری، FAQ، پیشنهاد ویژه، جذب سرنخ، آگاهی از برند، قبل‌و‌بعد و مسئله‌و‌راه‌حل
- انتخاب مدل جایگزین برای خطاهای موقت ارائه‌دهنده
- احراز هویت API با توکن Supabase
- اعتبارسنجی ورودی و محدودیت واقعی ۱۶ کیلوبایتی بدنه درخواست
- محدودیت پایدار و اتمیک درخواست‌های تولید بر اساس کاربر در PostgreSQL (۸ درخواست در هر ۱۰ دقیقه)
- ذخیره تاریخچه در Supabase با جداسازی داده کاربران از طریق RLS
- ویرایش محتوا، کپی و خروجی TXT/JSON
- تاریخچه نسخه‌های قبلی محتوا، ثبت snapshot هنگام ویرایش و امکان بازگردانی
- صفحه‌بندی تاریخچه با cursor پایدار و دریافت ۵۰ رکورد در هر صفحه
- پشتیبان کامل محتواها با دریافت همه صفحات تا سقف ۱۰٬۰۰۰ رکورد
- جست‌وجوی پیشرفته، پوشه، برچسب، علاقه‌مندی و خروجی گروهی JSON
- داشبورد تحلیلی حساب با بازه‌های ۷ روز، ۳۰ روز و کل تاریخچه ذخیره‌شده؛ تجمیع در PostgreSQL و مستقل از صفحه‌بندی رابط
- ثبت مصرف توکن و تعداد تولیدهای موفق Gemini برای هر حساب؛ سهمیه اعتباری هنوز نیازمند تعریف پلن است
- پروفایل برند قابل استفاده مجدد برای هر حساب: مخاطب، ارزش پیشنهادی، لحن، واژگان ترجیحی/ممنوع و CTA
- چک‌لیست و امتیاز ساختاری زنده برای کیفیت محتوا و انطباق واژگان برند
- تقویم محتوایی سبک برای تعیین زمان انتشار، نمایش موعدهای پیش‌رو و گذشته
- رابط فارسی، راست‌چین و واکنش‌گرا

## فناوری‌ها

- Next.js 16.4.5
- React 19.3.1
- TypeScript
- Node.js 24 LTS
- Supabase Auth و PostgreSQL
- Gemini API

## اجرای محلی

نیازمندی‌ها: Node.js 24 و npm.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

برنامه در `http://localhost:3000` اجرا می‌شود.

## متغیرهای محیطی

مقادیر واقعی را فقط در فایل محلی نادیده‌گرفته‌شده توسط Git و تنظیمات امن Render وارد کن. هیچ کلیدی را در GitHub یا کد سمت مرورگر قرار نده.

| متغیر | کاربرد |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | آدرس پروژه Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | کلید عمومی anon/publishable برای کلاینت Supabase؛ امنیت داده باید با RLS تضمین شود |
| `GEMINI_API_KEY` | کلید محرمانه Gemini برای تولید واقعی |
| `GEMINI_MODEL` | مدل اصلی؛ پیش‌فرض در کد: `gemini-3.8-flash` |
| `GEMINI_FALLBACK_MODEL` | مدل جایگزین؛ پیش‌فرض در کد: `gemini-3.5-flash-lite` |

اگر کلید Gemini تنظیم نشده باشد، API محتوای نمونه (demo) برمی‌گرداند؛ این خروجی تولید واقعی مدل نیست. سهمیه Gemini به طرح ارائه‌دهنده وابسته است و در صورت اتمام سهمیه، API پاسخ 429 با پیام مشخص برمی‌گرداند.

## ساخت و کنترل کیفیت

```bash
npm ci
npm audit --omit=dev
npm test
npm run typecheck
npm run build
```

GitHub Actions همین کنترل‌ها را برای Pull Request به `main` و push به `main` اجرا می‌کند. مقادیر Supabase در CI صرفاً placeholder هستند و هیچ داده یا سرویس واقعی را لمس نمی‌کنند.

## نکات امنیتی و عملیاتی

- policyهای جدول‌های `content_history` و `content_versions` مالکیت داده را با `(select auth.uid()) = user_id` کنترل می‌کنند.
- نسخه‌های قبلی در جدول جداگانه `content_versions` ذخیره می‌شوند؛ حداکثر ۱۰ نسخه اخیر هر محتوا در رابط نمایش داده می‌شود و با حذف محتوای اصلی، نسخه‌های آن نیز cascade حذف می‌شوند.
- کلید Gemini فقط باید در محیط سرور نگهداری شود.
- پروفایل برند در user metadata همان حساب Supabase ذخیره می‌شود؛ این داده فقط زمینه تولید است و مبنای مجوز دسترسی نیست.
- rate limit تولید محتوا در PostgreSQL و به‌صورت اتمیک ذخیره می‌شود؛ بین restart و چند instance مشترک است. اگر بررسی محدودیت در دسترس نباشد، API برای جلوگیری از دور زدن کنترل، با خطای 503 متوقف می‌شود.
- تاریخچه به‌صورت صفحه‌ای و ۵۰ رکورد در هر صفحه بارگذاری می‌شود؛ آمار و تقویم بر اساس صفحات بارگذاری‌شده محاسبه می‌شوند. برای دریافت همه محتواها از پشتیبان کامل استفاده کن.
- پشتیبان کامل محتواها تا سقف ۱۰٬۰۰۰ رکورد را دریافت می‌کند؛ snapshotهای نسخه‌های قبلی در جدول جداگانه `content_versions` ذخیره می‌شوند و در فایل پشتیبان فعلی نیستند.
- حداکثر ۱۰ نسخه اخیر هر محتوا در رابط نسخه‌بندی نمایش داده می‌شود.
- تقویم فقط زمان‌بندی داخلی است و محتوا را خودکار در شبکه‌های اجتماعی منتشر نمی‌کند.
- Supabase Auth leaked-password protection هنوز در تنظیمات پروژه غیرفعال است و باید از بخش Password Security فعال شود؛ این قابلیت در طرح Pro و بالاتر در دسترس است.
- سرویس فعلی Render روی پلن Free قرار دارد؛ برای دسترس‌پذیری همیشگی و مقیاس تجاری باید پلن و هزینه زیرساخت بازبینی شود.
- پیش از انتشار قابلیت‌های پرداخت، همکاری تیمی یا انتشار خودکار شبکه‌های اجتماعی، نیازمند اتصال، تنظیمات و تأیید جداگانه هستیم.
- خروجی AI باید پیش از انتشار توسط کاربر بازبینی شود. امتیاز کیفیت فعلی ساختاری است و صحت ادعاها را تضمین نمی‌کند.
