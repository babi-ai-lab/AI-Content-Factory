# AI Content Factory

وب‌اپلیکیشن فارسی برای تولید و مدیریت محتوای بازاریابی و برنامه‌ریزی کمپین‌های کسب‌وکارها.

نسخه آنلاین: https://ai-content-factory-6m32.onrender.com/

## قابلیت‌های پیاده‌سازی‌شده

- ورود و ثبت‌نام کاربران با Supabase Auth، تأیید ایمیل و بازیابی رمز عبور
- تولید کپشن، سناریوی ریلز، مجموعه استوری و متن تبلیغاتی با Gemini
- پشتیبانی از ۹ نوع کسب‌وکار و ۱۰ قالب تخصصی تولید محتوا
- انتخاب مدل جایگزین در خطاهای موقت ارائه‌دهنده
- احراز هویت API با توکن Supabase، اعتبارسنجی ورودی و محدودیت بدنه ۱۶ کیلوبایتی
- محدودسازی پایدار و اتمیک درخواست تولید در PostgreSQL (۸ درخواست در هر ۱۰ دقیقه)
- ذخیره تاریخچه محتوا با جداسازی داده کاربران از طریق RLS
- ویرایش، کپی، خروجی TXT/JSON، جست‌وجو، پوشه، برچسب و علاقه‌مندی
- تاریخچه نسخه‌ها، snapshot هنگام ویرایش و بازگردانی نسخه
- صفحه‌بندی تاریخچه با cursor و پشتیبان کامل تا سقف ۱۰٬۰۰۰ رکورد
- داشبورد تحلیل با بازه‌های ۷ روز، ۳۰ روز و کل تاریخچه؛ تجمیع سمت PostgreSQL
- ثبت تعداد تولیدهای موفق و مصرف توکن Gemini به تفکیک کاربر و مدل
- پروفایل برند قابل استفاده مجدد برای مخاطب، ارزش پیشنهادی، لحن، واژگان و CTA
- چک‌لیست ساختاری کیفیت محتوا و بررسی واژگان برند؛ این امتیاز صحت factual ادعاها را تضمین نمی‌کند
- تقویم محتوایی شمسی برای برنامه‌ریزی دستی زمان انتشار
- مدیریت کمپین‌های بازاریابی: هدف، مخاطب، کانال‌ها، وضعیت، چک‌لیست شش‌مرحله‌ای اجرا و اتصال محتواهای ذخیره‌شده به کمپین
- رابط فارسی، راست‌چین و واکنش‌گرا

## محدوده فعلی محصول

- اتصال حساب شبکه‌های اجتماعی و انتشار مستقیم یا خودکار در شبکه‌ها در محصول فعال نیست.
- تقویم، ابزار برنامه‌ریزی دستی است و خودش محتوا را منتشر نمی‌کند.
- همه امکانات فعلاً رایگان‌اند؛ درگاه پرداخت، اشتراک پولی و محدودیت ماهانه مصرف فعال نیست.
- ثبت مصرف AI فعال است. محدودیت‌های ارائه‌دهنده Gemini و زیرساخت میزبانی همچنان ممکن است اعمال شوند.
- سرویس فعلی Render روی پلن Free است؛ این استقرار برای آزمایش و بازخورد اولیه مناسب‌تر از تعهد به دسترس‌پذیری تجاری ۲۴/۷ است.

## اجرای محلی

نیازمندی‌ها: Node.js 24 و npm.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

برنامه در `http://localhost:3000` اجرا می‌شود.

برای بازیابی رمز عبور، دامنه Production را در Supabase Authentication → URL Configuration → Redirect URLs مجاز کن. پیش از عرضه عمومی، SMTP اختصاصی و قابل اتکا نیز برای ایمیل تأیید و بازیابی تنظیم شود.

## متغیرهای محیطی

مقادیر واقعی را فقط در فایل محلی نادیده‌گرفته‌شده توسط Git و تنظیمات امن Render وارد کن. هیچ کلیدی را در GitHub یا کد سمت مرورگر قرار نده.

| متغیر | کاربرد |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | آدرس پروژه Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | کلید عمومی anon/publishable برای کلاینت Supabase؛ امنیت داده باید با RLS تضمین شود |
| `GEMINI_API_KEY` | کلید محرمانه Gemini برای تولید واقعی |
| `GEMINI_MODEL` | مدل اصلی Gemini |
| `GEMINI_FALLBACK_MODEL` | مدل جایگزین |

در توسعه محلی، اگر کلید Gemini تنظیم نشده باشد، API خروجی نمونه (demo) می‌دهد و این خروجی تولید واقعی مدل نیست. در محیط Production بدون کلید Gemini، API با خطای 503 متوقف می‌شود و خروجی نمونه به‌جای تولید واقعی نمایش داده نمی‌شود. سهمیه و محدودیت‌های Gemini تابع تنظیمات ارائه‌دهنده است.

## ساختار اصلی

```text
app/
  api/generate/route.ts   # API سمت سرور، احراز هویت، اعتبارسنجی و تولید
  api/health/route.ts     # health check ساده برای میزبان
  globals.css             # طراحی و واکنش‌گرایی
  layout.tsx              # metadata، زبان فارسی و RTL
  page.tsx                # رابط اصلی
components/
  campaign-manager.tsx    # مدیریت کمپین و اتصال محتواهای ذخیره‌شده
lib/
  supabase.ts             # کلاینت Supabase
  server-controls.mjs     # اعتبارسنجی، محدودیت بدنه و rate limit
  content-quality.mjs     # تحلیل ساختاری کیفیت محتوا
tests/                    # تست‌های خودکار
supabase/migrations/      # migrationهای نسخه‌دار پایگاه داده
docs/ROADMAP.md           # نقشه راه و وضعیت تحویل
.github/workflows/ci.yml  # کنترل کیفیت در Pull Request و main
```

## کنترل کیفیت

```bash
npm ci
npm audit --omit=dev
npm test
npm run typecheck
npm run build
```

GitHub Actions همین کنترل‌ها را برای Pull Request به `main` و push به `main` اجرا می‌کند. مقادیر Supabase در CI placeholder هستند و به داده واقعی دسترسی ندارند.

## امنیت و عملیات

- جدول‌های داده کاربر با RLS و سیاست‌های مالکیت‌محور محافظت می‌شوند.
- کلید Gemini فقط باید در محیط سرور نگهداری شود.
- پروفایل برند در user metadata همان حساب Supabase ذخیره می‌شود؛ این داده مبنای مجوز دسترسی نیست.
- rate limit تولید در PostgreSQL ذخیره می‌شود و بین restart و چند instance مشترک است.
- خروجی AI باید پیش از انتشار توسط کاربر بازبینی شود.
- محافظت Supabase Auth در برابر رمزهای افشاشده هنوز در تنظیمات پروژه فعال نشده است.
- پیش از عرضه عمومی گسترده، تست مرورگر/یکپارچه، پایش خطا، بررسی بازیابی پشتیبان و بازبینی نهایی امنیت و ظرفیت لازم است.
